# Vimac

macOS 菜单栏 Vim 编辑工具。通过 Accessibility 读取当前文本框和设置选区，用宿主原生编辑命令修改文本，并在 Normal / Visual 模式显示块状光标覆盖层。

这是可运行的 MVP。自带试验窗口已经验证；微信、浏览器、IDE 等第三方控件还需要逐个验证，不承诺任意应用完整兼容。

## 构建与启动

运行环境目标 macOS 13+，开发使用 Swift 6.2.4 / Apple Silicon。测试使用 Swift Testing，当前工具链的测试运行库要求 macOS 14+；应用本身的 macOS 13 兼容性未实机验证。

```bash
bash scripts/test
bash scripts/build-app
open dist/Vimac.app
```

菜单栏常驻 `● Vimac · 待授权 / 启动中 / 就绪 / NORMAL / INSERT / VISUAL`，绿点表示监听运行中，橙点表示需要处理权限或监听异常。`就绪` 表示应用正在运行、尚未接管当前输入框。

首次没有权限时自动打开运行状态窗口并请求辅助功能授权。在系统设置中开启 **Vimac 应用自身**的权限；终端中的探针权限不能代替应用权限。授权后每两秒自动检测并连接监听，无需重新启动。若提示缺少输入监控权限，通过状态窗口中的按钮打开对应设置。

Normal / Insert / Visual 内部模式切换只更新菜单栏，不弹屏幕提示。开启或退出 Vim 接管时显示短暂提示；输入框不支持或接管失败时显示具体原因。点击菜单中的“运行状态 / 权限设置…”可查看当前应用路径、权限和监听状态；再次打开已经运行的应用也会显示此窗口。

本地打包使用 ad-hoc 签名，尚未做 Developer ID 签名和公证。建议在固定路径运行；重建后若系统权限失效，需要从系统设置重新授权。

打包前必须退出正在运行的 Vimac；脚本会拒绝覆盖运行中的签名二进制，避免代码身份失效。若已有权限条目但当前应用仍显示未授权，请删除旧条目并重新添加当前 `dist/Vimac.app`。

首次使用选择“打开试验文本窗口”，先在这个独立窗口验证操作，随后再测试目标应用。

## 操作

| 操作 | 按键 |
| --- | --- |
| 开启 Normal / 关闭 Vim 模式 | Ctrl+Option+V |
| 普通输入 | Normal 中按 `i` |
| 返回 Normal | `Esc` |
| 字符选择 / 取消选择 | `v` |
| 字符、逻辑行移动 | `h j k l` |
| 下个词首、上个词首、词尾 | `w b e` |
| 逻辑行首 / 尾 | `0 $` |
| 删除字符 / 整行 | `x` / `dd` |
| 复制整行 / 粘贴 / 宿主撤销 | `yy` / `p` / `u` |
| Visual 复制 / 删除 / 修改 | `y` / `d` / `c` |

Visual 中可以跨行、反向扩大和缩小选区。`c` 删除选择后进入 Insert。`yy/dd` 产生行型寄存器，`p` 放到当前行下方；外部剪贴板变化后以普通字符型文本粘贴。

网页编辑器的 Normal `j/k` 使用宿主原生上下方向键，以实际屏幕行落点为准，可能与逻辑行语义不同。飞书部分跨行 AX 选区请求会被修正，不能承诺 Visual 跨块或依赖精确选区的编辑都支持；选区不匹配时停止，不执行后续删除。原生文本框仍使用逻辑行移动。

网页正文从 `AXStringForRange` 读取，使英文 `e/b/w` 和字符移动使用与宿主选区一致的偏移。飞书的 `AXValue` 会额外插入换行，不能直接用于选区定位；若这正是两份文本的差异，则保留这些虚拟段落的单词边界，避免将相邻段落连成一个词。所有选区仍需精确匹配，0.1.7 的中间落点容错已撤回。日志用 `text.coordinates` 记录两种长度，不记录正文。

当网页范围文本缺失段落分隔符时，`dd/yy/0/$` 和行型粘贴暂时拒绝执行，避免把整篇文档当成一行处理；`j/k` 仍使用宿主原生方向键。网页端到端效果仍需逐场景验证。

Normal / Visual 使用 ANSI 物理键位，避免中文输入源把命令送进候选框。Insert 普通输入原样交给宿主；Vim 接管期间 Esc 的按下与松开均由 Vimac 消费，只返回 Normal，不触发网页的退出编辑或整块选择。关闭接管后 Esc 恢复给宿主。中文组词中请先完成候选选择再退出 Insert；跨应用候选取消尚未统一实现，不自动发送 Esc 或 Enter 代替提交/取消输入法。

焦点切换、权限失效、安全输入或 AX 失败时退出接管。Normal 中同一输入框更新文本或光标时同步最新快照并清除命令前缀，不自动退出；Visual 选区或正文被外部修改时退出，避免沿用失效锚点误操作。每次写操作仍重新核对快照。Normal / Visual 中使用 Cmd/Ctrl/Option 系统快捷键也会退出，再正常传给宿主；重新按开关键即可恢复。未知普通按键被吞掉，避免命令字符写入文档。菜单始终提供退出入口。

## 运行日志（开发排障）

配置和日志统一放在 `~/.vimac/`：`config` 保存配置，`vimac.log` 保存运行日志。首次启动自动创建缺失的默认配置，保留已有配置。

启动应用后自动追加到 `~/.vimac/vimac.log`，菜单中的“查看运行日志”可定位文件。每行是一条 JSON，包含时间、启动标识和顺序号；会话、命令编号把模式切换、按键路由、快照变化、选区请求及实际结果和退出原因串起来。Insert 只记录输入发生，不记录字符；不保存正文、网页地址、窗口标题或剪贴板内容。关闭 Vim 接管时不记录普通输入。

日志单文件最多 **30,000,000 字节（30MB）**。下一条记录会超限时清空旧日志，从文件头继续写，不生成备份；应用重启沿用同一文件。写入在独立队列完成，队列拥塞时丢弃日志并在后续记录的 `dropped` 字段报告数量，不阻塞编辑。磁盘写入失败时向标准错误报告，编辑继续运行。

复现故障后可以直接让开发助手读取这个固定路径，通常不必再逐步描述操作。选区不匹配仍会停止编辑，日志用于定位原因，不代表第三方兼容问题已经修复。

## 配置

选择“生成 / 打开配置”打开 `~/.vimac/config`，文件缺失时自动创建；UTF-8 JSON，示例见 [Resources/config.example](Resources/config.example)。只填写需要修改的字段即可，其余沿用默认值。保存后选择“重新加载配置”。非法配置保留上次有效版本，不部分生效。

```json
{
  "toggle_key": "ctrl+option+v",
  "cursor": {
    "color": "#FFFFFF",
    "style": "block",
    "opacity": 0.55,
    "width": "auto",
    "height": "auto",
    "border_color": "#777777"
  },
  "theme": { "mode": "system", "accent_color": "#66CCFF" },
  "key_mapping": { "normal": { "H": "moveLeft", "L": "moveRight" } }
}
```

- `cursor.style`：block / outline / bar；宽高为 auto 或正数 point（最大 200），透明度 0～1。
- `theme.mode`：system / light / dark，主题影响工具自身界面，不修改宿主。
- `key_mapping`：normal / visual，单键或双键映射到固定命令名称；不能覆盖 Esc 退出语义或产生前缀歧义，不支持 Insert 字符重映射、宏或任意脚本。
- 所有命令名称在 [Configuration.swift](Sources/VimCore/Configuration.swift) 默认映射表中；未覆盖的默认键仍然有效。

## 模块

- `VimCore`：无系统 I/O 的状态机、字素/UTF-16 转换、命令解析、配置校验。
- `MacAdapters`：事件 tap、AX 文本与焦点适配、串行会话协调、剪贴板和不抢焦点的透明光标面板。
- `VimacApp`：菜单栏、配置、权限提示。
- `VimacFixture`：独立进程的原生 NSTextView 试验窗口。
- `VimacProbe`：只操作自己启动的试验进程的真实 AX / 按键验证器。

## 验证

```bash
# 纯逻辑测试，无需辅助功能权限
bash scripts/test

# 真实 AX 与全局按键链路；会短暂打开并聚焦自己的试验窗口
swift build
.build/debug/VimacProbe

# 验证已通过 open 启动并授权的真实 .app，不启动探针自己的监听器
.build/debug/VimacProbe --external-app

# 只读检查前台输入控件，不输出正文、不改变选区或文本
.build/debug/VimacProbe --inspect-focus

# 只查询权限，不弹窗申请
.build/debug/Vimac --check-permissions
```

探针核对目标 PID；焦点离开试验进程即停止，不自动切回用户正在操作的输入框。字符断言临时使用 ASCII 输入源，测试结束且用户未另外切换时恢复原选择；应用正常运行不切换输入源。剪贴板临时粘贴只在结果确认且内容仍属本次操作时恢复。程序不保存正文、按键记录或剪贴板历史。

## 已知边界与后续验收

- 必须能可靠读取文本、读写选区并确认可编辑，否则拒绝开启。按键降级适配尚未实现，避免把不准确的系统单词移动冒充 Vim 语义。
- 第三方应用的编辑、撤销、通知、输入法表现需实测。未引入浏览器扩展、IDE 插件或私有 text marker 接口。
- 光标为覆盖层，无法通用隐藏宿主原生细光标；位置不可用时隐藏。多显示器、全屏 Space、遮挡、富文本与软换行仍需人工验证。
- 焦点有 AX 通知和 100ms 轮询后备；滚动事件合并后在约 16ms 发起几何刷新，命令完成立即更新光标。实际 33ms 绘制与 50ms 命令延迟目标尚未测量，AX 较慢的宿主不能据此承诺达标。鼠标点击会退出接管。
- 没有跨进程原子编辑事务。焦点检查缩小竞争窗口，但无法完全消除；不确定的修改不会自动重试。
- 撤销使用宿主 Cmd+Z，分组由宿主决定。纯文本粘贴不承诺富文本格式保持。超过 100 万 UTF-16 单元的控件退出接管。
- 当前未实现数字计数、操作符组合、宏、文本对象、块选择、多光标和当前键盘布局字符映射。
- 退出应用即移除监听与覆盖层；不更改宿主永久配置。退出不会撤销已经执行的文本编辑。
